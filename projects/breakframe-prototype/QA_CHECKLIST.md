# BREAKFRAME iPhone Safari QA Checklist

対象: projects/breakframe-prototype

## 座標変換・物理

- [ ] 画像を読み込み、奥行きの異なる上段・下段のブロックで、ボールが表示位置と一致してブロックに当たる。
- [ ] パドル中央へボールが落ちたとき、表示されたボールとパドルの位置が一致して反射する。
- [ ] パドルの左端・中央・右端をタッチし、表示パドルがタッチ位置に追従する。画面端でパドルがはみ出さない。
- [ ] 上段・下段のブロック破壊時、破片とパーティクルが破壊位置からずれない。
- [ ] 画面を縦横回転またはSafariの表示領域変更後、パドル・ボール・ブロックの表示と当たり判定が一致する。

## iPhone Safari入力

- [ ] Safariでtouch-action: noneが効き、パドル操作中にページスクロール・横移動が発生しない。
- [ ] タッチ開始でパドルが移動し、画像読み込み後の初回タップでゲームが開始する。
- [ ] タッチを画面端までドラッグしてもパドルが安全範囲内に収まる。
- [ ] 操作中に着信・通知・別指入力などでpointercancelが発生しても、以後の入力とゲームループが復帰する。
- [ ] 操作終了後にポインター捕捉が解除され、別のタッチ操作を受け付ける。

## 既存機能回帰

- [ ] レターボックス（全体表示）で画像が引き延ばされず全体表示される。
- [ ] 安全なクロップ（画面いっぱい）で画像処理スタイルを維持したまま表示される。
- [ ] リアル／ファミコン／ポリゴンの切替後も座標変換・衝突判定・タッチ操作が維持される。
- [ ] ボール落下後に再開確認が表示され、OKで最初から再開、キャンセルでゲームオーバー状態を維持する。
- [ ] リセットで画像・スタイル・fit設定を保持したままゲームだけ初期化される。

## 確認方法

- [ ] iPhone Safari実機で、contain/cover × リアル/ファミコン/ポリゴンを最低1回ずつ確認する。
- [ ] デスクトップのマウス操作ではなく、iPhoneの指操作で左・中央・右を各3回確認する。
- [ ] 可能ならSafari Webインスペクタで、コンソールエラー、pointercancel後のイベント停止、画面回転後の当たり判定を確認する。
