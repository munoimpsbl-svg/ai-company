# P003 SPEC

## 目的

グラビア事業部長AIが、既存WordPressサイトの状態を毎日確認し、編集長へ改善・分析・提案を報告するための仕様を定義する。

## 対象

- 既存WordPressサイト
- 既存記事
- SEO流入
- PV
- CTR
- 回遊率
- 写真集や関連商品の導線
- 内部リンク
- 記事改善候補

## 非対象

- 新規記事の大量生成
- 無断投稿
- 無断公開
- 無断のWordPress設定変更
- 許諾不明画像の使用
- SNS事業部のキャラクター運用変更

## AIの役割

グラビア事業部長AIは、毎日以下を行う。

1. サイト状況を確認する。
2. KPIの変化を要約する。
3. 改善候補を抽出する。
4. 優先順位を付ける。
5. 編集長が判断できる形で提案する。

## 入力情報

Sprint 1では、入力情報が未接続でもレポート生成できるようにする。

優先入力は以下とする。

- Google Search Console
- Google Analytics
- WordPress記事一覧
- WordPress管理画面またはエクスポートデータ
- アフィリエイト管理画面のCTR、CVR、売上
- 編集長からの指示
- 前回REPORT.md

未接続の入力がある場合は、レポート内に「未接続」と明記する。

## 出力

毎日、REPORT.mdに以下の形式で報告する。

- 実行日
- 今日の結論
- KPI状況
- 伸びた記事
- 落ちた記事
- 改善候補
- 内部リンク提案
- CTR改善提案
- 回遊率改善提案
- 注意事項
- 編集長への確認事項
- 明日の作業候補

## 判断基準

改善提案は以下の順で優先する。

1. 既存記事の検索流入改善
2. PVがある記事のCTR改善
3. 回遊率を上げる内部リンク追加
4. 写真集や関連商品の導線改善
5. 情報が古い記事の更新
6. タイトル、見出し、メタ情報の改善

## レポート品質基準

レポートは編集長がそのまま判断できる内容にする。

- 数値がある場合は数値で書く。
- 数値がない場合は未取得と書く。
- 推測と事実を分ける。
- 実行が必要な項目は優先度を付ける。
- WordPress変更が必要な項目は編集長承認待ちにする。

## 承認フロー

AIは提案まで行う。

以下は編集長承認後に実行する。

- WordPress記事編集
- タイトル変更
- メタディスクリプション変更
- 内部リンク追加
- アフィリエイトリンク変更
- 画像差し替え
- 公開、更新、削除

## Sprint 1 完了条件

- PROJECT.mdがある。
- SPEC.mdがある。
- TASK.mdがある。
- REPORT.mdがある。
- CHANGELOG.mdがある。
- REPORT.mdのテンプレートで日次報告を継続できる。

Failure Handling

データ取得できない場合

・エラーにしない
・未接続としてREPORTへ出力
・次回再試行

## Sprint 2

目的: P001 Core Platformを利用してWordPressサイトを解析し、REPORT.mdを自動生成する。

### 対象

- WordPress情報取得
- タイトル取得
- カテゴリ取得
- タグ取得
- 記事一覧取得
- 解析結果のREPORT.md出力

### 保存

Google Drive保存はP001 Core Platformの`core.drive.save_report()`を利用する。

Google Drive未接続時はP001のローカルフォールバックにより`output/reports/`へ保存する。

### 禁止事項

- WordPressへの書き込みは禁止。
- 投稿は禁止。
- 更新は禁止。
- 削除は禁止。
- 解析のみ行う。

### 設定

対象サイトURLは`.env`または環境変数で指定する。

```text
P003_WORDPRESS_URL=https://example.com
```
## 記事下書き追加仕様

P003は`ARTICLE_QUEUE.md`を読み込み、`編集長確認欄`が`GO`の行のみWordPressへ下書き作成する。

入力:

- `ARTICLE_QUEUE.md`
- `ARTICLE_DRAFTS/*.md`

出力:

- `ARTICLE_DRAFT_RESULT.md`

制約:

- WordPress作成ステータスは`draft`のみ。
- 公開は禁止。
- 既存記事更新は禁止。
- 削除は禁止。
- カテゴリ・タグの新規作成は禁止。
- 推測で本文を生成しない。
